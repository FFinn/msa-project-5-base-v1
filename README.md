## Что подготовлено

- технологическое обоснование по всем заданиям;
- ADR-001, ADR-002 и ADR-003 с единым журналом архитектурных решений;
- демонстрационный прототип Apache Airflow с чтением источника, условным ветвлением, повторными попытками и уведомлениями об успехе и ошибке;
- контекстная C4-диаграмма и дополнительная контейнерная диаграмма для задания 2;
- Dockerfile, приложение экспорта и Kubernetes CronJob для задания 3;
- ADR по Spring Batch, локальный демонстрационный прототип и целевая архитектура TradeWare;
- проект наблюдаемости для задания 5: метрики, логи, трассировки и оповещения;
- пример правил оповещений Prometheus.

## Что необходимо выполнить локально перед финальной сдачей

Два требования нельзя корректно заменить статическими файлами — проверяющему нужно показать **реальный запуск**:

1. **Задание 1:** запустить демонстрационный прототип Airflow по `task-1/results/DEMO.md` и добавить реальные скриншоты Airflow и MailHog.
2. **Задание 3:** запустить CronJob/Job в MiniKube по `task-3/results/DEMO.md` и добавить реальные скриншоты `kubectl`, журналов выполнения и сформированного CSV.

После этого следует проверить все файлы, создать запрос на слияние из `submission` в `main` и отправить проверяющему ссылку на него.

## Диаграммы

Диаграммы хранятся в редактируемом формате Draw.io (`*.drawio`), в исходниках PlantUML/C4 (`*.puml`) и, где подготовлено, в PNG (`*.png`). Исходники PlantUML можно открыть в среде разработки с подключаемым модулем PlantUML или отрисовать через PlantUML из командной строки. Для C4 используется C4-PlantUML.

При переносе результатов в финальный репозиторий сохраняйте структуру `task-N/results` исходного репозитория Яндекс Практикума.
